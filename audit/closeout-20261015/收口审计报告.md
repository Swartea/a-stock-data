## 依赖核查

候选链只部分成立：

- Canonical identity / registry 应提供稳定对象身份；Market Snapshot 的核心指数 universe 需要映射到这些 canonical IDs。
- `market_snapshot` 当前是快照容器契约；`market_state` / `market_availability` 描述状态与质量；service 聚合两者并依赖可注入数据边界。
- Golden snapshot 是 service 输出的固定回归数据，应在 service 后。
- Static view 是展示层，应消费 snapshot JSON，不拥有 identity、registry 或 provider 获取职责。

建议集成顺序：canonical ID/registry ownership decision → Snapshot service + availability → golden fixture → static view。Package metadata 可独立。

Global Daily-K 与 Market Snapshot 冲突：两边都有指数 ID/universe/alias 概念。建议唯一 canonical registry 定义稳定 ID、市场、display name、provider symbols 和 alias；Market Snapshot 的 universe 只列其展示成员并引用 canonical ID，不另行声明身份；Global Daily-K 的 provider adapter 仅负责 canonical ID ↔ provider symbol/取数，不拥有 Snapshot registry。通过合同测试确保同一上证/深证等身份无重复 ID，并验证 alias 与 provider symbols 不混为 canonical identity。此为技术方案，尚未改生产实现。
