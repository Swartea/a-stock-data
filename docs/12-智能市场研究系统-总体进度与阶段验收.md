## 一、当前总体判断

截至 2026-10-07，项目已经具备较扎实的 A 股数据与 V3 单股分析基础，并开始建设 Research Engine 与全球主要指数日 K 能力；但最终目标中的 **Market Snapshot、K 线可视化、重要信息筛选、关联分析和电脑/手机研究台** 尚未形成完整闭环。

**总体完成度估计：约 35%～40%。**

这个比例不是工程代码完成度，而是相对于最终产品目标的阶段性判断。

| 能力 | 当前状态 | 估计完成度 |
|---|---|---:|
| A 股原有数据能力 | 已较完整，可继续复用 | 85%+ |
| V3 单股分析与报告 | 已可实际使用，持续模块化 | 80%～85% |
| Pipeline / orchestration 模块化 | 已推进到 Phase 1H/1I/1J 一带 | 75%～80% |
| 全球主要指数日 K | 已实现第一版与 A 股 fallback | 65%～70% |
| Market Snapshot | 尚未形成面向用户的完整快照 | 20%～30% |
| K 线展示 | 数据已有基础，交互展示尚未形成 | 10%～20% |
| 重要信息统一筛选 | 原系统有新闻/公告/资金能力，但未形成统一筛选链路 | 10%～20% |
| 关联分析 | 尚未形成正式证据链与关系层 | 约 10% |
| 研究台闭环 | 尚未形成电脑/手机侧完整产品体验 | <10% |

## 三、五阶段进度

### 阶段 1：Market Snapshot

**目标**：用户打开系统后，先看到 A 股为核心、港股和美股主要指数的市场状态、日 K 概览、数据时间和数据质量。

**当前已有：**

- 全球 9 个主要指数 identity / registry。
- 统一日 K 返回结构。
- provider 来源与降级信息。
- A 股指数 fallback。
- 原 A 股系统已有较丰富的行情、板块和资金基础。

**仍缺：**

- 面向用户的统一 Market Snapshot schema / service。
- 指数状态汇总。
- 新鲜度、缺失、降级状态统一展示。
- A/HK/US 市场状态在一个入口内的组合。
- 与后续 K 线页、信息流、板块页的跳转关系。

**阶段状态：进行中。**

**阶段验收标准：**

用户能在一个入口回答：

1. 今天/最近一个交易日主要市场发生了什么；
2. 看到的数据对应什么时间；
3. 哪个数据源提供；
4. 是否发生降级、缺失或延迟；
5. 可以继续进入对应指数或研究对象。

---

### 阶段 2：K 线展示

**目标**：把日 K 数据变成真正可研究的图表，而不是只返回 JSON / Python 数据。

**当前已有：**

- 9 个指数的统一日 K 数据基础。
- 时间区间、市场时区、数据来源等底层契约。

**仍缺：**

- K 线图组件。
- 统一对象选择与周期切换。
- Market Snapshot → K 线的导航。
- 图表与研究对象 identity 的稳定绑定。
- 手机侧可用布局。

**阶段状态：未形成产品闭环。**

**阶段验收标准：**

用户可从市场快照进入某指数，查看正确的日 K 图；图表中的对象、时间范围、数据源和数据时间与底层返回一致。

---

### 阶段 3：重要信息筛选

**目标**：不是“把新闻都列出来”，而是从新闻、公告、板块资金等信息中筛出真正值得研究的内容。

**当前已有：**

原 A 股系统已有：

- 个股新闻。
- 财联社电报。
- 全球资讯。
- 公告。
- 板块资金流。
- 个股资金流。
- 研报等信息基础。

**仍缺：**

- 跨来源去重。
- 时效性排序。
- 重要度评分/规则。
- 来源质量表达。
- 对象映射。
- “为什么值得关注”的解释。
- 与 Market Snapshot 的统一入口。

**阶段状态：未开始正式闭环。**

**阶段验收标准：**

用户能回答：

1. 今天最重要的事情是什么；
2. 为什么系统认为重要；
3. 信息来自哪里、何时发布；
4. 对哪些市场/指数/板块/股票相关；
5. 可以回到原始证据核验。

---

### 阶段 4：关联分析

**目标**：把股票、板块、指数、新闻和资金之间的关系组织成可解释、可追溯的研究路径。

**当前已有：**

- Research Engine 的 identity / registry 基础。
- 原系统中已有板块、资金、新闻、个股等分散数据。

**仍缺：**

- 统一 Evidence schema。
- 关系类型定义。
- 时间顺序与证据链。
- 新闻 → 板块 → 股票 / 指数的映射。
- 对象 → 相关重要信息的反向查询。
- 直接证据 / 统计关联 / 待验证假设的分层表达。

**阶段状态：早期。**

**阶段验收标准：**

系统能展示“为什么认为这些对象有关”，并保留具体来源、时间、映射依据和不确定性，而不是直接把相关性写成因果。

---

### 阶段 5：研究台闭环

**目标**：形成真正每天可以打开使用的电脑/手机研究台。

完整主线：

`Market Snapshot → K 线 → 重要信息 → 关联分析 → 研究结论 / 回看`

**当前状态：尚未形成。**

**阶段验收标准：**

用户能从市场状态开始，在一次连续会话中完成：

1. 看市场；
2. 看走势；
3. 看最重要的信息；
4. 查看相关板块/股票/指数；
5. 核验证据；
6. 形成研究结论；
7. 保存并在之后继续回看；
8. 电脑和手机保留一致的核心研究上下文。

## 六、不可破坏的约束

新研究系统继续遵守以下红线：

- 不顺手修改 V3 量化公式。
- 不顺手调整评分口径或权重。
- 不顺手改变三价位定义和计算含义。
- 不把数据缺失伪装成 0 或确定值。
- 不把 fallback 隐藏起来。
- 不把统计相关直接写成因果。
- 不以数据源数量、端点数量或代码量替代产品进度。
- 继续采用小步迁移、契约测试、独立验收的方式推进。
