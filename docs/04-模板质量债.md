## A. 报告模板层债（4-phase plan 范围外）

> 4-phase 实施聚焦 **skill 端点 + Section Registry + SKILL.md 导航**，不涉及报告模板层
> （操作口诀/三价位/北向口径/价格快照/K线时点），故 A 区债项**多数仍 OPEN**。

### 债 1：结论与操作自相矛盾（严重，OPEN）

**现象**：报告"🔴 看空 43 分｜不建议进场（清仓回避）"，但操作口诀写"现价分两批进场、持有 3-6 个月"。

**根因**：模板只套了买入结构，未按多空结论切换操作模板。

**修法**（未实施）：模板加多空状态机——空/震荡/多三态各有独立模板。

### 债 2：缺支撑/压力显式字段（严重，OPEN）

**现象**：老板硬要求"结论 + 支撑/压力/止损"缺一不可。当前只有止损/止盈（其实是"现价 +X%"反推的），没有真正从技术面算出的支撑/压力。

**修法**（未实施）：在技术面章节加显式三价位表（MA60/前低/筹码峰/布林下轨 取最近者）。

### 债 3：北向资金 370.5 亿口径异常（待查，OPEN）

**现象**：报告写"✅ 北向净流入 370.5亿"。美湖股份流通市值 102 亿，全市场当日北向净流入 370 亿才算合理。

**怀疑**：数据源把"全市场北向净流入"当个股口径填入了。

**修法**（未实施）：1) 查 a-stock-data 北向接口是返回单股还是全市场；2) 若全市场，模板必须区分"全市场北向"和"个股北向"。

### 债 4：筛选池价格快照与验证时点不一致（部分修，PARTIAL）

**现象**：任务 4 v1 稿 `screener_pool.csv` 13:45 写盘，但 12 只 v2 验证后用陈旧价自算的三价位有 7 只与 v2 实时价矛盾。

**根因**：
- 筛选脚本未落价格快照时间戳
- 验证脚本未做时点强校验
- 三价位计算未用 v2 同源实时 K 线

**Phase 0 修法（已落地）**：
- ✅ Task 0.1 V3 命名 bug 修复：结果文件 `result_v3-{HHMM}.json` 时间戳化（commit `fb86ac3` + `7422b1f`），run_log 同步加时点
- 600693 三次跑验证：跑 1/2/3 间隔 80s，三份 run_log 互不覆盖（任务 4.1 报告 ✅）

**仍 OPEN**：
- ❌ 筛选脚本 `screener_pool*.py` 生成 CSV 时**未落** `price_snapshot_time` 列
- ❌ 验证脚本加载时**未做强校验**（> 1 小时未告警）
- ❌ 三价位计算未走 mootdx → 腾讯 二级降级链

### 债 5：盘中快照 K 线 last_bar 滞后（未触及，OPEN）

**现象**：盘中（<15:00）跑 V3，baostock 日线仍停在 N-1，筹码/技术面用陈旧 K 线。

**裁定**（梁大锋 9-7，序列 49 重申）：
- 盘中快照版：last_bar 非当日记 WARN 合规，但必须标数据时点
- 盘后定稿：必须 last_bar == 最新交易日（18:07 baostock 收盘更新后重跑）
- 方案 A（腾讯实时价补当日合成 bar）已否决：估算值喂进换手率与筹码分布 = 假精度

**Phase 0-4 状态**：**未触及**。4-phase 实施不涉及此债。仍按 plan 留作长期 backlog。

**遗留口径债**：V3 主脚本 level 三档 ok/warn/na（非当日记 WARN）与 snapshot_guard 的 BLOCK 判据不一致，代码层面尚未对齐。

## B. Skill 层债（4-phase 实施相关）

> 4-phase 实施已直接处理 skill 数据层债。所有状态基于实测（PEG=9.56 / 600693 三跑 89.0s avg / 23 sources / 5 sections 全注册）。

### 债 6：PEG 公式偏差（已修 ✅）

**现象**：原 PEG = `pe_fwd / cagr_pct`，600693 算得 3.85，与 ifind 41.73 偏差 -91%。

**根因**：`pe_fwd`（东财动态 PE）口径与 ifind 不一致。

**修法**（Task 0.3，commit `b85cee5`）：PEG = `pe_ttm / cagr_pct`，口径对齐 ifind 静态 PE。

**实测**：600693 PEG = 9.56（数量级与 ifind 41.73 接近，差因 cagr_pct 取值口径不同；落在 spec §8.2 区间 1-12 内）。✅

### 债 7：V3 命名 bug（已修 ✅）

**现象**：`result_v3.json` 每次跑覆盖，run_log 散落无追溯。

**修法**（Task 0.1，commit `fb86ac3` + `7422b1f`）：`result_v3-{HHMM}.json` 时间戳化 + run_log 同名同步。

**实测**：600693 三次跑生成 `result_v3-145557.json` / `result_v3-145728.json` / `result_v3-145857.json`，互不覆盖。✅

### 债 8：资金流 push2 风控（部分修 🟡）

**现象**：`push2.东财域名` 触发 WAF 限流（9-7 资金面-5日主力跑失败）。

**修法**（Task 0.2，commit `2ccfff6` + `942f952`）：资金流域名切到 `push2his.东财域名`。

**实测**：600693 跑已使用 push2his，但 WAF 仍偶发 502/限流（3/3 跑均 error，**代码层修复已生效，运行时风控为预存在 issue**）。

**仍 OPEN**：
- 当日资金流 fflow 502 偶发（WAF 限流，需 retry/降级）
- 概念板块 slist 风控持续 fallback

### 债 9：新闻退避 23s 串行（已修 ✅）

**现象**：新闻舆情 `3 + 4*attempt` 退避策略，4 次重试累计 21s。

**修法**（Task 0.4，commit `cc5cba6` + `e3e5991`）：`0.8 + 1.2*attempt` 退避，4 次重试累计 ~6s。

**实测**：600693 新闻舆情 14-16s（仍略超 15s 预算，因 sina RTT），但已从 23s 优化。✅

### 债 10：5 个新章节缺失（已实施 ✅）

**现象**：原 V3 主分析器只 4 旧 fetcher + 3 supplement，缺互动易/股东户数/分红/打板/全市场龙虎榜。

**修法**（Phase 1-2）：
